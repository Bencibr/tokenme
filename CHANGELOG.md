# Changelog

All notable changes to TokenMe are documented in this file. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [Unreleased]

### Added

- **Quota banners at 80 % and 100 %** — the panel now posts a native notification the moment a vendor-metered window first crosses **80 % used** ("已用 83%（剩余 17%）", titled `Qoder · 5 小时`) and once more when it **runs out** ("额度已用完（100%）"; the language follows the panel's). The real-quota sources get banners — the strip's windows and credit wallets — while §5 budgets stay the panel's own business. Edge-triggered, not level-triggered: each line fires once per window instance and the fact is persisted beside the index (`notify-state.json`, `0600`, tmp + fsync + rename, 30-day retention), so a restart replays nothing and the 60 s quota-pass TTL can re-publish the same sample all it likes — the machine is idempotent. A **posted** banner is what advances the tier: a delivery the system refused is retried on a later pass (one attempt per window per 60 s). A window renewal — its reset instant jumped past the few seconds of probe jitter (> 5 min) — re-baselines silently; a tier that falls back re-arms without a word (the path that also covers credit top-ups, whose `resets_at` never moves); and a window first seen already past 80 % is baselined quietly, because the banner marks the crossing, not the state — only an already-exhausted first sight announces itself. The permission prompt is raised lazily, by the first banner actually due (once per run, on its own thread, so a prompt nobody answers cannot wedge the worker) — a user who never crosses a line is never asked — and a denial logs the System Settings path on first occurrence instead of silently swallowing banners.
- **Delivery is notify-rust's UNUserNotificationCenter backend; the Tauri notification plugin was tried and dropped** — on desktop that plugin's permission API is an empty stub (permission_state answers Granted unconditionally), its `show` posts through the deprecated NSUserNotification path and discards the delivery error in a fire-and-forget task, and in dev it would post as `com.apple.Terminal`. The threshold machine needs the real results at both ends — the permission verdict and whether a banner actually posted — so delivery goes through notify-rust with its `preview-macos-un` feature, the UNC path the spike proved posts from an ad-hoc-signed bundle; its Windows side rides the same crate's WinRT toast backend under the app's AppUserModelID once installed. `TOKENME_TEST_NOTIFY=1` posts a test banner through the same gate (permission request included) for QA of the permission flow, and the Windows backend is cross-checked compiling for `x86_64-pc-windows-gnu`. The honest boundary: a bare `cargo run` has no bundle identifier, so desktop banners are off there by nature and the worker says so in the log — the .app is the real surface.
- **The pointer to the OS toggle lives in the panel** — while the system would not deliver a banner (permission denied, or never asked) and there is a vendor window to warn about, the quota section carries a one-line guide above its list: 开启系统通知后，额度跨过 80% 或耗尽时会自动弹出提醒 — with an **开启通知** button when the permission is undecided (it raises the system prompt, which is macOS's own decision UI; the state is polled afterwards so the row retires the moment the answer lands) or **去开启** after a denial (opens System Settings' notification pane, deep-linked straight to TokenMe's row). It is dismissible (忽略) and the dismissal is remembered per state — observing the permission change re-arms it, so a grant now never suppresses a later denial — and it renders nothing at all once banners can post, so a granted machine never sees it. The status is a new read-only pair of commands (`notify_status` / `notify_enable`), QA-pinned by `TOKENME_NOTIFY_STATE` and `?notify=`. In the same batch: the `TOKENME_TEST_NOTIFY` test post now fires after the run loop is up — fired at setup it could not deliver ("Mainthread not running"), a failure a denial had been masking.
- **Settings became a four-tab sheet, and every probe is now something you can turn off** — the one long scroll is now 通用 / 提醒 / 高级 / 关于 at a fixed 65 % of the panel height, with the body scrolling inside the selected tab and 版本 · 检查更新 · 退出 pinned in the footer so the escape hatch never scrolls away; tabs carry no entry counts. Two rows open a list *inside* the same sheet (`‹ 返回` back, `›` a page here, `↗` another surface — 服务器与同步 borrows the existing server sheet rather than reimplementing it). What the old sheet could not do was stop polling: **高级 → 自动探测配额** is the master gate and **逐工具探测** the per-vendor list, wired through `usage_quota::collect_gated(budget, gate)`. A gated probe sends no request but its cache is still read, so the row keeps its last answer on screen instead of going blank, and while the gate is closed the quota section says **已停止探测 · 数据停在 N 分钟前** — quiet numbers and stale numbers must not look identical. Moving either switch deliberately does **not** fire a refresh: a forced pass would delete the answer the user just chose to keep, and the panel's own 60 s pass picks it back up. The list defaults to the probes this machine has actually answered and offers 显示全部 for the ones it never has; the row set comes from `usage_quota::inventory()` — the registry describing itself (which probes exist, which have a host-process gate, which have answered here) rather than a front-end copy that drifts — pinned by a test that names the probes no host gate can reach. The four with no mapping (Copilot, Gemini CLI, Kimi Code, MiniMax Code) are tagged 无退出门, because that list is the only way to stop them. **提醒** grew the choice the banners were missing: 提醒档位 (80 % 与 100 % / 仅 100 % / 关闭) and 静默工具, which mutes selected windows while their numbers keep refreshing — `notify::Gate` filters **delivery** and still advances the window's recorded tier, because a tier left frozen at its old value would post a stale banner the instant the user changed their mind. A list under a closed gate or a denied notification permission greys its switches and says why instead of showing toggles that look live, and 退出后暂停 moved into the per-tool page where the host gate belongs — which is also what keeps all four tabs inside the 65 % box. The tray display-mode chip and 桌面气泡 (Windows-only) keep their places; the quota section's guide line is unchanged.
- **`scripts/check-i18n-parity.py` — the two dictionaries and their call sites are now gated, not eyeballed** — TypeScript pins the key sets against each other, but it cannot see a placeholder that diverges between the two sides (`{n}` in zh against `{count}` in en renders the raw token), a call site handing `t()` the wrong name (`{ lab }` against a string that says `{label}` typechecks and prints `{label}` on screen), or dead copy left behind when a control is deleted — and `t()` answers `undefined` for a miss, so every one of those symptoms is a single blank or raw row. The gate checks the key sets, the placeholder sets per key, that each literal `t("key", { … })` hands exactly the names its string asks for, and that no key in the dictionary is unreachable; it refuses to skip a dictionary line it cannot parse, and it is wired into `build-macos.sh` beside the theme-parity gate so it runs even with `--fast`. Controls, because a gate nobody has falsified is decoration: four broken copies (an English key removed, a placeholder renamed on one side, an orphan key added, a value written unquoted) each fail, and a call site renamed to `{ lab }` fails with the file and line. The first run that read the file correctly (two parser holes earlier: a value written across two lines, and a key reached through a `` `set.tab.${k}` `` template) found **six keys nothing referenced** — `read.hour.tail`, `set.quit.btn`, `srv.a11y`, `srv.copy.fail`, `srv.install.fail`, `srv.next` — left behind by earlier UI iterations; they are deleted, and the quit button now says 退出程序 with 关闭面板并退出托盘进程 as its tooltip, which is where the two `set.quit*` strings went instead of being dropped.

### Fixed

- **No console window on Windows when a quota probe shells out** — the Copilot probe reads its credential through the user's own `gh auth token`, and `gh` is a console binary: started from a GUI process (the tray app owns no console), Windows allocates one for the child and the default terminal paints it — a black window that took focus once per probe TTL on every machine that has GitHub CLI installed, whether or not the user runs Copilot at all. The spawn now carries `CREATE_NO_WINDOW`, the flag the Antigravity CLI and atomcode probes already carried for exactly this reason, and the panel's own link buttons (`cmd /c start` behind 发邮件 / Releases / 日志) are quietened the same way. The CLI is unaffected: a console child started from a terminal inherits that terminal and never opens a second window. Because the defect is invisible in review and loud on the user's screen, the batch adds `scripts/check-no-window-spawns.py` — every `Command::new` reachable from a Windows build must either name a program that cannot allocate a console (a GUI-subsystem binary, or one Windows cannot resolve) or carry the flag within 16 lines. Controls, as any gate needs them: the pre-fix `copilot.rs` taken from HEAD fires exactly one finding at line 127, and the fixed tree answers CLEAN over 142 files. Both spawn shapes are cross-checked compiling for `x86_64-pc-windows-gnu`.
- **Check-for-updates now only checks** — the About tab's 立即检查 button was wired straight to the download-and-install flow (`runUpdate`): one click fetched the latest release, streamed the bundle, verified its sha256, swapped it in and relaunched the panel — with no version comparison anywhere on that path, so an install already running 0.1.5 against the 0.1.5 release downloaded and reinstalled itself. The button now calls `check_update` and nothing else; the answer lands in the footer (已是最新版本 vX / 发现新版本 vX), and 下载并安装 / 重启到新版本 stay behind the footer buttons that only a genuinely newer version raises. `download_update` grew the gate too, rather than trusting its caller: it re-fetches the release and answers 已是最新版本 instead of downloading when that version is not newer than the running one — a re-pointed tag, or a caller that skipped the check, would otherwise quit and restart the panel for a swap that changed nothing. The same pass fixed `is_newer`'s missing precedence: the flat `a[0]>b[0] || a[1]>b[1] || a[2]>b[2]` let the patch digit alone decide, counting `0.1.6` as newer than `0.2.0`; it is a componentwise tuple comparison now, with tests pinning `0.1.6` vs `0.2.0`, `0.1.10` vs `0.2.0` and double-digit patches comparing numerically. A failed check also stopped answering an empty message: background paths (the boot check, the toggle-on check) filter by phase and stay silent as before, while a manual click shows 检查失败：无法连接更新源 instead of a button that visibly did nothing.

## [0.1.5] — 2026-10-07

### Added

- **Kimi Code** — usage from the CLI's `wire.jsonl` (v1 and v2) and from the desktop app's embedded runtime home, plus live plan windows (5-hour / weekly / monthly) from the vendor's own `/usages`. Credentials are read-only: the probe never refreshes or stands in for your login. (Superseded within this release — see Changed: the probe now rotates the access token and persists the pair.)
- **MiniMax Code** — usage from the dated session streams under `~/.minimax`, plus the plan's 5-hour / weekly windows and both credit wallets (purchased and check-in). The ~1-hour access token is renewed in place from the app's own stored refresh token and written back atomically in the app's own format, so the app and the panel stay signed in together.
- **Qoder desktop quota** — the probe reads the 0.4 desktop app's own auth record (`auth.v1.dat` beside its Chromium profile, keychain-paired on macOS, DPAPI on Windows) when the IDE's encrypted snapshot is not available.
- **Homebrew delivery** — `brew install --cask tokenme` for the panel and `brew install tokenme-cli` for the CLI, via the `Bencibr/homebrew-tokenme` tap that self-bumps from each release's own `sha256.txt`.
- **Supervised engine and the "Updates stopped" badge** — the panel restarts its engine loop after a panic or an unexpected exit (capped backoff, reason in `panel.log`), and the header states the report's age once it goes stale, so frozen numbers no longer look identical to quiet ones.
- **The Windows installer wears the brand and asks whose machine it is on** — the NSIS bundle had shipped Tauri's stock look: a default icon (an empty `INSTALLERICON` define let `makensis` fall back to its own), an English-only wizard, and a hardcoded per-user install into `%LOCALAPPDATA%`. `installerIcon` / `uninstallerIcon` now point at the app's own icon — `ExtractAssociatedIcon` hashes the setup exe and the installed app to the same PNG — the wizard lists SimpChinese before English with its language selector on, and `installMode: both` offers 所有用户 (Program Files) against 只为我 on every interactive run. `both` rides MultiUser's `highestAvailable`, so an admin sees one UAC consent at launch even on the per-user path, and the quiet upgrade grows the `/currentuser` flag that `/S` alone no longer implies; logs, the price cache and the index all resolve through per-user data dirs, so a Program Files install still writes where the user can.
- **The Linux collector, end to end** — `tokenme export` ships a window of the index as a gzipped JSONL bundle plus a sha256 manifest (tmp+rename, `0600` on unix); `tokenme import` validates hash, sums and schema version and merges in one all-or-nothing transaction, so re-importing the same file changes nothing. The panel engine merges `~/tokenme-sync` before every publish decision. `scripts/build-linux.sh` cross-builds fully static musl binaries and `scripts/install-linux.sh` wires a systemd `--user` timer (cron fallback when the user manager is unreachable) with `--every`, `--push` and `--uninstall`.
- **Machine scope** — `event_rollup` gained an origin column, so every period, breakdown, call series and session list folds under 全部机器, 本机 or any single remote by name from a header dropdown that re-summarizes without re-ingesting, and hides itself entirely while nothing has been imported. The session list's `LIMIT` is applied in SQL, so a busy local machine can no longer starve a remote's list empty.
- **In-panel SSH pull** — the footer's 服务器 surface probes a host, pins its SSH fingerprint on first connect (TOFU), provisions a dedicated key, uploads the static collector and fetches bundles on a per-server schedule; removing a server cleans up both ends. The password authenticates that one setup connection and is never stored.
- **Filled form fields grow a trailing clear control** — every server-sheet field (host, user, port, name, password, key path, passphrase) renders through a `ClearableInput`: the × shows only when there is something to clear, sits inside the field's right edge, and clearing keeps the field focused — the button swallows its own mousedown so clicking it never blurs the input first, and the parent's change handler travels as text so clearing is an ordinary empty value. The wrapper reserves the field width whether or not the control is showing, and the label speaks both languages (清除 / Clear).
- **Cline desktop sub-agents get their project back** — the desktop app writes an agent's transcript inside the parent session directory but its meta into a sibling `<session>__agent_<uuid>/`, so 9,238,243 prompt tokens of real sub-agent work reached the tool column unattributed. The label now walks a candidate chain (own sibling meta → the agent dir's meta → the containing session's meta), and the accuracy gate scores our stage totals against the app's own `metadata.usage` / `aggregateUsage` ledger per settled session.
- **A repair path for derived labels** — an event whose stored totals equal the fresh reading now takes a newer `project`/`model` in place (totals still never move backwards), the touched days' rollup buckets are rebuilt in the same pass, and `IngestReport` counts those as `relabeled`.
- **`scripts/check-theme-parity.py`** — parses the three colour blocks (light `:root`, the `prefers-color-scheme` block, the 深色 pin) and fails on any name, order or value drift between the two dark ones. `build-macos.sh` runs it before the cargo gate, and it runs even with `--fast`. It now also binds `index.html`'s two boot-shell colours to `--ink-3` / `--accent`, because that copy of the palette lives outside theme.css by necessity.
- **The cold start now has something to say at every stage, measured frame by frame.** `index.html`'s pre-paint shell used the app's own class names, so on the frame it exists for it had no stylesheet: text in the corner and two arcs with no stroke. It carries its own critical CSS now, bound to the real palette by the parity gate, and the recording shows it painting — brand ring and 正在索引本机用量… centred — around +3 s into a cold start. The stretch before that is not a page problem: from the moment the window is on screen (~+1.4 s) until the page paints, every pixel is the **native window backing**, and no markup can reach it. So the note is drawn by AppKit as well — a system spinner above one teal line, centred as a group, 10 pt apart like the page's own card — and its retirement moved off bundle execution onto the first real report, because taking it away at `boot` left the sheet bare again from +3.2 s to +8.1 s, which is exactly what the recording caught. The spinner is not decoration: a static line on an empty sheet was reported as a dead panel on 2026-10-07, and motion is the only thing that layer has to say "working" with. The two milestones are now logged separately (`the page booted …` / `the page reported content …`) because the difference between them is where the wait lives.
- **`scripts/verify-cold-start.py`** — the instrument that measures the panel's first composited frame: it quits the app, records the display, cold-starts it with the panel opening itself, then finds the panel by pixels (its configured 400×660 size, hanging off the menu bar) and reports when it first appears, when it first draws anything, and where it landed. Three traps are built into it: a still screenshot and a video frame are encoded differently, so the baseline must come from the recording itself; another window of a similar size is not the panel; and behind a lock or a sleeping display the recorder writes nothing, which is exit code 2 and never a verdict.
- **Two gates on the version's homes** — `the_version_lives_in_four_homes_and_they_all_agree` binds root `Cargo.toml`, the panel's `Cargo.toml`, `tauri.conf.json` and `package.json` to the compiled version, and `the_release_manifest_never_lies_about_its_own_assets` allows `latest.json` to lag but never to advertise an installer it does not name. All 24 adapter crates now inherit the workspace version, so `release.sh` reaches every one of them (two were pinned at `0.1.0` and moved with no release).
- **The panel's first figures now come off disk, not off the scan.** Every publish writes the finished report to `report.json` next to the index (tmp + fsync + rename, `0600`), and a launch reads it back before it has detected a source, opened a price table or run a query — **3–22 ms** measured, against the 1.1–5.6 s the same first publish costs in the same rounds (and 6.8–24.9 s across this machine's earlier runs). Interleaved A/B on this machine's 170 MB index, three rounds each, figures-on-screen (`the page reported content`): 6,691 / 1,572 / 4,682 ms before, **1,284 / 905 / 1,126 ms after**; re-measured with the display awake, 2,449 and 3,172 ms. What that leaves, named honestly: the remaining term is no longer the report at all but the **webview's own page boot** (`the page booted`, 0.8–3.1 s in these runs, and 19.4 s once immediately after the bundle was replaced on disk, with every cache cold) — the engine now answers in 2–3 ms and waits for the page. What it restores is exactly what the user last saw, so the footer says so: a 上次扫描的数据 chip with the age the report itself carries (from the last scan · N min ago), and the quota strip goes back to 探测中 because a vendor window sampled an hour ago is not this run's answer. The restore is refused — and the old wait returns unchanged — when the cached report was folded under a different machine scope, on a different local day (its 今日 would be yesterday's totals under today's label), more than an hour ago, or by a clock that has since moved backwards; and a restored report is never written back, so a snapshot cannot chain. While one is on screen the engine-death warning (`数据已停止更新`) is suppressed: a scanning engine is not a dead one.
- **Cold-start telemetry** — the boot path logs its phases (`restore / detect / pricing / index open / has-events / sources / report`) and the panel logs when the page first reports content, so a slow open is attributed with numbers instead of guessed.
- **QA pins** — `?qpending=1` reaches the quota section's wait state, `?restored=<min>` the restored-first-frame chip at any age, `?pending=<s>` the footer's busy readout that many seconds after the click, `?stale=<min>` the frozen line and `?sync=<hours>` the sync badge; none of them are reachable from a hand-authored fixture, which always answers as if everything had settled.

### Changed

- **Kimi Code's quota probe renews its own expired access token** — through the vendor's refresh contract, persisting the rotated `refresh_token` back into `~/.kimi-code/credentials/<name>.json`. This supersedes the read-only claim in this release's own Kimi Code entry. Three probes now write a rotated credential back — MiniMax Code already renewed in place, and Cline's gateway token does the same — each into the tool's own store, atomically, and only where that tool's own login is what the probe is reading; the remaining probes stay read-only.
- **The footer's left corner stopped describing the price table and started describing the numbers on screen.** The event count left first (it only repeated the details page's 数据源 line), then the provenance went onto a badge's tooltip, and now the badge itself is gone — `models.dev` with its 4,213 keys was the state on almost every machine at almost every minute, which is chrome, not information. What stays in that corner is the panel's own condition: an always-on 最后刷新 clock saying when the figures were last recomputed — seconds for its first minute, so a manual refresh visibly restarts it at 刚刚, and a 刷新中 spin in place of the age while the pass that click started has not published yet — the 上次扫描的数据 chip while a restored report is on screen, the amber 数据已停止更新 chip with the last pass's age once the engine goes silent (the clock and this chip are the same fact pointing opposite ways, so they never show together), and the amber 陈旧 warning for a price table over 24 h old with no fetch behind it. Saying plainly what that removes: which listing the costs were priced from (models.dev, the local cache, the snapshot compiled into the app, nothing) and how many keys it holds are no longer displayed anywhere — the panel was their only surface, `tokenme pricing explain` answers per model rather than per table, and `?psource=` went with the badge it drove.
- **Two waits got their own lines** — the Linux-sync badge moved off the figures line to a row of its own, and the quota section's 探测中 spinner is centred in the area its list will occupy instead of a strip under the section label.
- **The whole-file integrity check left the panel's first render** — `PRAGMA quick_check` reads every page (0.4 s warm, 3.6 s cold on a 170 MB index) and used to run inside `Index::open`, in front of the first report. It is now `Index::verify_integrity()`, called by the panel after the first publish and before the first write, and by the CLI straight after open: every launch still verifies and still heals a damaged image, but measured engine startup before the panel could render went from 6,402 ms to 378–2,340 ms.
- The accuracy gate (`scripts/verify-totals.py`) learns Kimi Code's and MiniMax Code's stages — including MiniMax's own vendor-side usage table as a third opinion — plus an identity check for antigravity's retry boxes.
- READMEs list the two new tools (22 built-in adapters); the user guide gained the Kimi / MiniMax log paths, the in-place token-renewal note, and the frozen-badge troubleshooting row.

### Fixed

- **antigravity retry billing** — only retry boxes carrying their own `responseId` count as their own call. Copies of the parent's stream (81,260 of the 81,727 boxes on the machine measured) and id-less boxes no longer bill twice, recovering the 17 genuinely distinct attempts they were hiding.
- **OpenCode v2 sessions** — the newer `session_message` table (role in the `type` column) is read alongside `message`, and rows updated in place are no longer skipped by the resume cursor.
- **Qoder app lookup off macOS** — the auth-record directory search gained the Windows `%APPDATA%` fallback instead of assuming macOS paths.
- **The Windows process reads `TokenMe.exe` again** — `b668ec7` lowercased the binary while dropping the `-bar` suffix, and Task Manager has shown `tokenme.exe` on every install since; `mainBinaryName` returns to the product's own casing. The upgrade path survives it untouched: the uninstaller-first flow keys on `productName` (never changed), the installer deletes a previous binary name that differs from its own — so the lowercase-era `tokenme.exe` is removed on upgrade — and Windows folds `%LOCALAPPDATA%\TokenMe` onto the directory the old installs already use.
- **The server sheet accepts typing on Windows** — the tray panel is non-activating by design (opening must not pull focus from whatever you were editing), and on Windows `set_focusable(false)` maps to `WS_EX_NOACTIVATE`, so WebView2 received no key events at all: every text field in the server wizard rendered but swallowed every keystroke (macOS never showed this, because an NSPanel routes keys without activating). A field that takes focus now borrows a keyboard session — the frontend watches focusin/focusout over inputs and textareas and the Rust side flips focusability for its duration — and a fresh open resets the flag, because the session can outlive the hide path and tao's `MARKER_DONT_FOCUS` is one-shot: left set, every show after the first would foreground the panel.
- **跟随系统 + a dark OS lost the modal scrim** — the media-query block never declared `--today` / `--scrim`, so the light defaults fell through and dimmed the sheet with a dark veil on a pure-black panel; the 深色 pin also kept a stale pink on `--cat-18`, so one tool drew two colours on the two theme paths.
- **The blank card on a cold start is gone, and what is left is named with numbers.** Two causes were measured and closed: the engine's first publish used to wait on the whole-file integrity read (6,402 ms of startup before the panel could render; `Index::verify_integrity()` now runs after the first publish), and the window's first frames belonged to no layer the page could reach — they are the native backing, which is why three builds of markup in `index.html` changed nothing. `panel::show_boot_note` draws the line in AppKit instead, and four recordings of the installed app now measure **no bare frame at all**: the panel's first frame on screen (~+1.3–1.7 s) already carries it. What remained was not a blank frame but a wait — the first report cost 10–27 s on a 170 MB index while `detect / pricing / sources / report` were all in front of it. That wait is now answered at the source rather than painted over: the first frame is the previous run's own report read off disk (3–22 ms, labelled), and the scan's fold lands behind it as the second frame.
- **The panel opened in the bottom-left corner** when nothing supplied a tray rectangle (a relaunch, a QA open, the single-instance hand-off): the fallback only clamped whatever position the window server had chosen. It now anchors under the right end of the menu bar, and says so in `panel.log` when the session exposes no monitors at all — which is the one case that genuinely cannot be placed.
- **A stale fingerprint froze Cline's history** — a desktop sub-agent's transcript stops growing when its agent exits while the meta that names its workspace can land later, so 226 rows stayed unlabelled even after the labelling fix; the fingerprint now carries the label's freshness, and both discovery paths agree on it.
- **Fixtures stopped naming a person's machine**, and the antigravity port test now drives the shipped loopback filter instead of re-implementing it — with a dual-stack `127.0.0.1` / `::1` pair that must count once.
- **The release gate never compiled the shipped app's own crate** — `apps/tokenme-bar` is excluded from the root workspace, so `cargo test --workspace` could not see the panel's 37 tests, including the anchor and engine-loop ones. `build-macos.sh` now runs the panel's tests as part of the same gate.
- **Documentation that the code contradicted** — the READMEs, `docs/COMMANDS.md` and `docs/internal/ADAPTERS_DESIGN.md` called the quota probes read-only, which three of them (MiniMax Code, Kimi Code, Cline) have not been since they started renewing short-lived tokens in place; the Gemini CLI's real blockers were named instead of a vague boundary; the AgnesCode token file was documented at a Linux path on a macOS-first app; the cache was described as per-vendor TTLs where the project has one shared 5-minute TTL; and the design notes had no section at all for the two newest tools.
